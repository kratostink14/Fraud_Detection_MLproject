# FraudShield — Fraud Detection System

Это мой учебный проект по машинному обучению. Я строил систему для обнаружения мошеннических транзакций на синтетическом датасете PaySim.

Главное с чем пришлось разобраться — сильный дисбаланс классов: мошенничество составляет всего **0.13% от 6.3 миллиона транзакций**. Стандартные подходы здесь не работают, и это сделало задачу интересной.

---

## Результаты

| Метрика | Значение |
|---|---|
| ROC-AUC | **0.9977** |
| Recall (обнаружение фрода) | **0.86** |

Модель обнаруживает **86% мошеннических транзакций**.

## Что я сделал и чему научился

### Feature Engineering
Самое интересное решение в проекте — я создал два новых признака, основанных на математических расхождениях в балансах счетов:

```python
df['errorBalanceOrig'] = df['newbalanceOrig'] + df['amount'] - df['oldbalanceOrg']
df['errorBalanceDest'] = df['oldbalanceDest'] + df['amount'] - df['newbalanceDest']
```

Идея простая: если после транзакции баланс не сходится — что-то не так. По SHAP-анализу эти признаки оказались самыми важными для модели.

### Работа с дисбалансом классов
Вместо того чтобы искусственно увеличивать количество примеров фрода, я использовал `scale_pos_weight=100` в XGBoost. Это говорит модели: "ошибка на мошеннике стоит дороже, чем ошибка на честном клиенте".

### Настройка порога классификации
По умолчанию модель использует порог 0.5. Но я построил Precision-Recall кривую и выбрал порог **0.7** — так модель реже блокирует честных клиентов, сохраняя при этом высокий Recall.

### Сравнение моделей
Протестировал три подхода: Logistic Regression, Random Forest и XGBoost. XGBoost показал лучший результат по всем метрикам.

## Как запустить

**1. Скачай датасет**

[PaySim на Kaggle](https://www.kaggle.com/datasets/ealaxi/paysim1) → положи в `data/raw/PaySim_data.csv`

**2. Установи зависимости**

```bash
pip install -r requirements.txt
```

**3. Запусти preprocessing и EDA**

```bash
python src/preprocessing_and_eda.py
```

**4. Обучи модель**

```bash
python src/model_building.py
```
